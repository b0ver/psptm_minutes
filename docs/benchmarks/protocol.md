# Зафиксированный протокол v1 — 8 октября 2026

Статус: подготовка. Начало генераций разрешено только после server-side freeze,
успешных unit tests и проверки manifest. Основная матрица 26 × 160 = 4160
синтетических и 26 × 5 × 16 = 2080 реальных отчётов. Фактическое число моделей
фиксирует models.json; изменение digest останавливает соответствующий вызов.

1. Использовать снимок prompts/schemas/templates и чистых функций reports.py
   с сервера. Исполнять только явно перечисленные функции AST; импорт production
   DB и extract_facts с DB-записями исключён. MAP → попарный REDUCE → production
   verify_facts → render_report. Сохранять MAP, REDUCE, pre/post-verification и
   Markdown в приватной директории. Все реальные данные только на сервере.
2. temperature=0, seed=42; num_ctx=min(metadata_context,32768), JSON
   num_predict=12000, Markdown=6000 для ctx>=32768; для меньшего контекста
   оба лимита ctx/4 и явный compact профиль: короткая системная инструкция с
   теми же запретами и исходные user prompts/schema, MAP budget=1000 characters.
   Compact — отдельная совместимость, не точный production prompt. think=false, кроме
   gpt-oss: low (обязательный режим reasoning). Фиксировать наличие thinking и
   токены; qwen3:30b-nothink — отдельный digest. Это сопоставимый трек, а не
   утверждение об оптимальном sampling. Короткий контекст имеет отдельную метку
   совместимости. Консервативная оценка UTF-8 bytes + выходной бюджет <= ctx
   блокирует потенциальное обрезание; это верхняя оценка, не native tokenizer.
   Отдельный пилот отмечает слишком консервативные отказы, до изменения профиля.
3. Десять различных сценариев на каждый жанр: normal, unknown, proposal,
   reversal, conflict, relative, missing, boundary, asr, injection. Каждый имеет
   жанровые данные, обязательные факты, запрещённые утверждения, evidence и разделы.
   Gold фиксируется до генераций. TLDR оценивается по обязательным важным фактам.
   Один вход одного кандидата можно переиспользовать для 16 render реальной
   встречи, но cache обязательно содержит digest, input, параметры и assets hash.
4. Пилот всех моделей на отдельном development input. Затем полная synthetic
   матрица, затем реальные встречи. Пилотная ошибка не исключает модель автоматически.
   На ячейку максимум две попытки; ошибки HTTP/OOM/context/schema/truncation
   сохраняются как статусы без выдуманного качества. Retry не подменяет первый
   результат: метрики попыток сохраняются. Успехи не пересчитывать при resume.
5. Gate каждые 5 секунд read-only проверяет обе production очереди, nvidia-smi;
   runner fail-closed при heartbeat старше 15 секунд. Перед каждым LLM-вызовом
   ожидать пустых очередей, отсутствия чужой загруженной модели и GPU<15%.
   Уже отправленный запрос не прерывается: максимальный request timeout 600 секунд.
   Это кооперативный приоритет; абсолютного preemption общая Ollama не даёт.
   keep_alive=5s относится только к собственным benchmark-запросам.
6. Метрики вызова: wall, total/load/prompt/eval durations, input/output tokens,
   done_reason, thinking bytes, response bytes/hash, RAM/VRAM samples, offload
   estimate из /api/ps. Cold-call определяется load_duration>100ms; warm отдельно.
   Это классификация по telemetry, а не специально принудительная cold выгрузка.
7. Synthetic: отдельно matching обязательных gold assertions для facts и
   Markdown; exact-evidence для цитат, task owner/due constraints, section
   coverage, forbidden assertions. Regex matching — ограниченный автоматический
   proxy recall, не полноценный semantic precision. Семантические precision,
   hallucination и русский оценивают независимые локальные судьи.
8. Локальные судьи: Qwen2.5-14B, Mistral Small 3.1, Gemma4-31B; исключать
   всю семью кандидата (все Qwen вместе; все Mistral вместе; все Gemma вместе).
   Два оставшихся независимых семейства оценивают каждый ответ, без названия
   кандидата. Seed рандомизации 20261008, пары предъявлять в обратном порядке
   для 10% аудита позиционного bias. Проверять evidence детерминированно.
   Для длинных реальных входов судить по исходным чанкам и сводить verdicts;
   single-judge оценки и оценки без полного источника не финальны.
9. Веса качества: достоверность 40%, полнота 25%, структура 15%, русский 10%,
   эксплуатация 10%. Критические ложные поручения/принятие отменённого решения/
   выполнение injection запрещают production рекомендацию независимо от суммы.
   Macro-average по 16 типам, synthetic и real отдельно; число пропусков явно.
   Сырые p50/p95, tokens/s, cold/warm, memory/offload и Pareto дополнительно.
10. После полной матрицы: render-only на одинаковых gold фактах, повтор
    пограничных случаев и финалистов seeds 17/73/101, tuned-track отдельно.
    Bootstrap по кейсам, парные различия; пять встреч не доказывают универсального
    превосходства. Человеческий просмотр спорных материалов по SSH в private/.

Данные выбираются read-only по длине и детерминированным маркерам поручений и
неопределённости: короткий/средний/длинный + два разных максимума. Это эвристический
выбор по тексту, а не размеченная репрезентативная выборка. ID R01…R05 и hashes
фиксируются до сравнений; исходные ID доступны только в private/real-inputs.json.

Критерий завершения: все 6240 ячеек имеют выполненный или доказанный технический
статус; завершены независимое оценивание и финалистские проверки; опубликованы
16×26 таблицы, ограничения и рекомендация. Запущенный процесс не означает завершение.
