# ADR 0003: факты встречи и типы разборов Telemost Meeting Kit

Дата: 8 октября 2026. Статус: принято по запросу владельца интегрировать приложенный набор и применить его к текущим транскриптам.

## Решение

Сохранена исходная копия набора в vendor/telemost-meeting-kit (41 файл), её SHA-256 — config/meeting_kit/source-manifest.json. YAML-шаблоны преобразованы в JSON для нашего runtime; дополнительных Python-зависимостей не требуется. В интерфейсе доступны все 16 типов. По умолчанию готовятся короткий итог, конспект встречи, поручения, основные смыслы и оглавление. Дополнительный тип можно запросить после транскрибации.

Новый контур работает с неизменённым сохранённым транскриптом: MAP по фрагментам с перекрытием и сводкой предыдущей части, иерархический REDUCE, проверка цитат, рендер выбранных шаблонов. Факты и отдельные отчёты хранятся в новых таблицах meeting_analysis и meeting_reports. Исходные протоколы и реестр поручений не заменяются. Создание нового шаблонного отчёта не добавляет поручения в реестр и не отправляет их в Telegram или по email.

Шаблоны: tldr, action_items, meeting_notes, protocol, key_meanings, chapters, followup_email, project_sync, standup, one_on_one, retro, sales_call, customer_interview, hr_interview, brainstorm, lecture_notes. Письмо по итогам — только локальный черновик.

## Адаптация исходного набора

- Сохранён наш нативный /api/chat Ollama, запрет облачных моделей, digest allowlist, локальная проверка endpoint, trust_env=false и отсутствие redirect. OpenAI-совместимый клиент набора с произвольным base_url не используется.
- Контекст задаётся в запросах (32768; до 12000 выходных токенов для JSON и 6000 для Markdown), настройки общей службы Ollama не меняются. Модель остаётся разрешённой qwen3.5:9b; новые веса не скачиваются.
- JSON-ответы проверяются по закрытым inline-схемам набора. Структура, обязательные поля, типы и enum проверяются в приложении.
- Нечёткое совпадение 0.78 и утверждение LLM сами по себе не подтверждают цитату. Даже после модельной перепроверки требуется дословный источник. Неподтверждённые задачи/решения сохраняются в rejected_items с причиной и не поступают в факты для рендера.
- Сроки остаются словами участников; due_date=null. Дата встречи опциональна и вводится явно, дата загрузки не подменяет её. Имена и сроки в задачах дополнительно проверяются по цитате.
- Диаризация и правка ASR из набора не запускаются. У существующего STT нет меток говорящих, поэтому текст передаётся как речь неопознанного говорящего, без выдуманной идентификации. ASR, CUDA и прежняя обработка остаются действующими.
- Промпты чата и сводного дайджеста сохранены как исходные материалы; интерактивный чат и отдельный сводный дайджест не реализованы этим изменением.

## Надёжность и интерфейс

Очередь разборов обрабатывается отдельным контейнером analysis-worker, под собственным эксклюзивным advisory lock 90601009. GPU worker продолжает транскрибацию независимо; оба используют существующую Ollama на хосте. При старте прерванные разборы и отчёты возвращаются в очередь. Кэш фрагментов переживает сбой; факты привязаны к хешу транскрипта, метаданных и ресурсов набора. Готовые отчёты повторным запросом не перегенерируются, новые типы используют готовые факты. Повторный запрос ошибочных типов возобновляет обработку.

Прогресс показывает этап и число фрагментов/отчётов. Markdown отображается через DOM/textContent без исполнения HTML, есть таблицы и ссылки-таймкоды в исходный транскрипт; отчёт можно скачать как Markdown. Авторизация остаётся по ADR 0002: только локальный порт через SSH.

Dockerfile разделяет слой зависимостей и код приложения, чтобы изменения шаблонов/кода больше не требовали повторной установки CUDA-библиотек.

## Границы проверки

Точная цитата подтверждает источник, а не автоматически правильную интерпретацию решения или поручения. Все результаты — AI-черновики для проверки человеком. Темы, цифры и смыслы тоже могут содержать ошибки модели или исходного STT. Иерархическая свёртка может упустить детали; исходный транскрипт и отдельные фрагменты сохраняются. При превышении допустимого контекста возвращается безопасный код ошибки, вместо молчаливой обрезки в нашем клиенте.
