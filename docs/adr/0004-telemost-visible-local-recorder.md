# ADR 0004: видимый ассистент Телемоста и локальная запись

Дата: 8 октября 2026. Статус: тестовый прототип по запросу владельца.

## Решение

Отдельный Docker-контейнер telemost-agent запускает Chromium, входит гостем по прямой HTTPS-ссылке и представляется «Ассистент протокола · запись». Камера и микрофон выключены, реальные устройства хоста не подключены. В браузере доступны только виртуальные media devices, их исходящие дорожки принудительно отключены. Применяется штатная команда Телемоста «Записать на компьютер»; команда записи на Яндекс Диск и облачный ИИ-конспект не используются.

Нативная запись соответствует настройкам организатора и уведомляет участников о начале записи. Прототип не пытается обойти комнату ожидания, запрет записи, авторизацию или CAPTCHA. Guest flow проверяется на тестовом звонке. Интерфейс Телемоста может изменяться, поэтому ошибки шага требуют повторной проверки UI, а не скрытого переключения на перехват аудиодорожек.

Файл сохраняется в /data/telemost/<session UUID>/recording.webm на сервере. Затем отдельный сервис отправляет его существующему API загрузки, где он попадает в прежнюю очередь GPU STT и пяти универсальных разборов. Исходный файл агента сохраняется. Реальная AI-обработка выполняется только на хостовой Ollama и в Docker STT, как принято ранее.

## Управление

В основном интерфейсе добавлен раздел «Подключить ассистента к Телемосту»: ссылка, название, максимальная длительность (до 120 минут), подтверждение разрешения записи, статус, завершение и переход к созданной карточке встречи. Агент одновременно обслуживает одну встречу. Останавливает запись по явной команде, заданной длительности или спустя 30 секунд после того, как останется единственным участником (при доступном счётчике участников).

Порты агента наружу не опубликованы; команды проходят через существующий loopback API и его Origin guard. Прямая ссылка ограничена host/path, не принимает произвольные URL, credentials, query или fragment. Метаданные сохраняются атомарно в JSON; журнал процесса не содержит URL встречи и содержимого разговоров. Снимок состояния может содержать данные встречи, доступен только через локальный интерфейс и нужен для диагностики.

## Контейнер и ограничения MVP

Непривилегированный UID 10001, cap_drop ALL, no-new-privileges, read_only, writable tmpfs, отдельный предел RAM/CPU, без доступа к GPU и секретам базы/Telegram. Chromium использует временный XDG config/cache в /tmp. Браузер работает без Chromium sandbox в контейнере; Docker ограничения остаются, дополнительная browser sandbox/сетевой allowlist требуют отдельного усиления перед длительной эксплуатацией. Версия Playwright закреплена; системный Chromium из официального Debian репозитория фиксируется фактическим образом сборки.

Перезапуск прерывает активный звонок и отмечает сессию agent_interrupted; восстановление самого звонка и нативной записи не реализовано. Уже сохранённые файлы сохраняются. При неопределённом результате POST загрузки нет автоматического повтора, чтобы не создавать дубликаты; отображается upload_uncertain. Нужны дальнейшие проверки устойчивости длинной записи, аварийного восстановления и разных настроек организатора.

Штатная локальная запись: [справка Яндекса](https://m.yandex.ru/support/yandex-360/customers/telemost/desktop/ru/call/record). Вход: [справка Яндекса](https://www.yandex.ru/support/yandex-360/customers/telemost/web/ru/call/join). API управления встречами: [описание](https://yandex.com/dev/telemost/doc/ru/); вход записывающего участника через этот API не заявляется.

## TLS доверие для серверов связи

В тесте mdd.yandex.net и hdrc.yandex.net отклонялись Chromium с ERR_CERT_AUTHORITY_INVALID. Для цепочки Russian Trusted Sub CA добавлен официальный Russian Trusted Root CA только в системное/NSS хранилища контейнера агента. Проверка имени, срока и цепочки TLS остаётся включённой. Хранилище NSS живёт в отдельном tmpfs, исходный публичный сертификат закреплён в образе. Установка на macOS или хостовый Linux не производится. [Источник и отпечаток](../../integrations/telemost/certs/README.md).
