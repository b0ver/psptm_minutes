# Проверка отмены запроса без потоковой выдачи

Рабочий код использует stream=false. Это видно в app/ai.py и app/reports.py. Клиент получает полный ответ после завершения генерации. Успех потокового probe не подтверждает отмену этого режима.

Новый файл scripts/ops/ollama_nonstream_cancel_client.py проверяет этот режим на синтетическом запросе. Он не читает записи встреч. Он не сохраняет текст ответа. Он не меняет модели или настройки Ollama. Старый потоковый клиент и его mounts остаются неизменными.

## Профили

Профиль задает параметры запроса. Параметры соответствуют рабочему коду кандидата 3fa09d4.

| Профиль | num_ctx | num_predict | Формат |
| --- | --- | --- | --- |
| extract-json | 8192 | 2500 | JSON schema |
| analysis-json | 32768 | 12000 | JSON schema |
| analysis-text | 32768 | 6000 | Текст |

Проверка использует синтетический список чисел. Ее JSON schema не является схемой пользовательского отчета. Она проверяет транспорт и параметры генерации. Она не проверяет качество отчета.

## Ограничения клиента

Клиент требует CAPACITY_CANCEL_ACK=synthetic-only. Он требует разрешенное окно GPU. Он проверяет локальный endpoint. Он проверяет точный model digest. Неизвестный CANCEL_PROBE_PROFILE вызывает отказ до HTTP.

Собственный таймер ограничивает запрос двумя минутами. SIGTERM, SIGINT и SIGALRM закрывают клиент. Клиент сохраняет только профиль, параметры, payload hash и состояние HTTP. Данные trace callback не сохраняются. Событие http11.send_request_body.complete устанавливает phase=awaiting_response. Этот этап означает, что клиент отправил тело запроса. Поле response_received остается false до получения полного ответа.

Нормальный ответ дает exit 2. Отмена клиента дает exit 130. Ошибка дает exit 1. Ни один код клиента не доказывает серверную отмену. Его server_cancellation_verified всегда false.

## Последовательность GPU-проверки

1. Проверь фактические handles прежних попыток.
2. Подтверди завершение прежнего unit.
3. Проверь production-очереди и все состояния агента.
4. Проверь лабораторный сервис и его очередь.
5. Проверь общий lab.lock и GPU.
6. Подготовь одну новую изолированную попытку.
7. Зафиксируй image ID, model digest и хеши всех mounts.
8. Создай привязку idle worker для этого job.
9. Запусти job через проверенный capacity watchdog.
10. Дождись phase=awaiting_response при response_received=false.
11. Подтверди работу GPU native Ollama двумя снимками с SM>0.
12. Продолжи наблюдение активной работы не менее пяти секунд.
13. Останови только свой systemd unit.
14. Запусти post-stop observer сразу после остановки.
15. Проверь client_cancelled, response_received=false и exit 130.
16. Проверь непрерывное прекращение GPU-работы по контракту observer.
17. Сохрани совместный receipt с временными метками.
18. Дождись естественного освобождения модели.

Для потокового клиента нужны растущие streaming-счетчики. Для нового клиента счетчики не применяются. Нужны подтвержденная отправка тела, незавершенный HTTP-ответ и работа native Ollama. Оба вида доказательств нельзя смешивать.

Новый совместный receipt принимается только при свежей последовательности. Watchdog должен завершиться после сигнала оператора, а не после чужой нагрузки или естественного конца ответа. Поздний idle не подтверждает прежнюю отмену. Полный corpus остается запрещен до принятой проверки нужных режимов и освобождения модели.

## Уточнение admission

Команда bind-idle-worker теперь создает только привязку identity. Она не подтверждает доступность GPU. Ее ready=false означает admission=not_checked.

Watchdog сначала проверяет production idle. Затем он запускает только свою CPU-БД. После ее health он выполняет полную проверку GPU. Для resident context остаются обязательными десять секунд GPU=0% и все прежние проверки. Только затем watchdog запускает клиента. Повторная длительная GPU-проверка перед CPU-БД удалена. Критерий перед запросом к модели не ослаблен.

При отказе GPU client остается created. Своя БД завершается. Такую попытку нельзя считать модельным вызовом. Watchdog сохраняет измерения отказа в приватном idle-worker-refusal.json, если отказ возник в resident-context gate.

## Выполненные проверки

Локальный Docker/PostgreSQL-набор дал 333 passed за 13.44 s. Осталось одно предупреждение Starlette. Тестовые контейнеры и сеть удалены.

Локальный HTTP-тест подтвердил отправку nonstream POST. SIGTERM закрыл соединение до ответа. Тесты проверили три профиля, отказ неправильному digest, ACK, окно и профиль. Тесты также проверили отсутствие текста ответа и данных trace в status.

Это не GPU-приемка Ollama. Новый клиент еще требует CI и установки отдельной неизменной копии.
