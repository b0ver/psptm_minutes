# Яндекс Календарь и автоматический вход в Телемост

12 октября 2026, 09:41 МСК. Интеграция развёрнута на Bender: API, агент Телемоста и новый calendar-scheduler. Перед обновлением проверено отсутствие активных сессий. STT, analysis-worker, Telegram и Ollama не перезапускались. При первом развёртывании календарь владельца ещё не был подключён. В 10:11 МСК подключены «Мои события», прочитаны 22 события со ссылками Телемоста; реальные автоматические встречи ещё не проверены.

## Подключение

Откройте личный веб-интерфейс через SSH-туннель и раздел «Яндекс Календарь · автоматическое подключение к встречам».

1. В Яндекс ID → Безопасность → Пароли приложений создайте пароль типа «Календарь». Введите почту аккаунта и этот пароль в веб-форму. Пароль в чат или Telegram отправлять не нужно.
2. Нажмите «Найти календари», выберите календарь и подключите его. Часовой пояс по умолчанию — Europe/Moscow; его используют для событий без явной зоны, если сервер не передал зону календаря.
3. Проверьте ближайшие события и причины пропуска. В «Настройках автоматического входа» подтвердите разрешение на запись, выберите типы разборов и включите автоматику один раз для календаря.
4. Ассистент дальше сам проверяет события и входит по расписанию. Для отдельной встречи доступны пропуск, возврат в расписание, управление записью и переход к готовому протоколу.

Отдельный пароль приложения и CalDAV описаны в [справке Яндекса](https://yandex.ru/support/yandex-360/customers/calendar/web/ru/data-exchange/synchronization/sync-desktop). Новый пароль может заработать через 2–3 часа. Подключение к календарю даёт доступ к его данным, но не авторизует браузер агента под Яндекс ID. В этом выпуске агент входит гостем.

## Поведение расписания

Плановое чтение календаря выполняется раз в пять минут, задания проверяются раз в пять секунд. Перед входом событие проверяется заново; до наступления настроенного времени входа дополнительные запросы для него не выполняются. Горизонт — 14 дней. По умолчанию вход начинается за минуту; допустимое опоздание — пять минут. Зона события сохраняет местное время повторов при переходе на зимнее или летнее время. Поддержаны RRULE, исключения EXDATE и перенос отдельного экземпляра RECURRENCE-ID.

Ссылка извлекается из X-TELEMOST-CONFERENCE, LOCATION, URL и DESCRIPTION и проходит строгую проверку Телемоста. Формат нестандартного поля описан в [документации Яндекса](https://www.yandex.ru/support/yandex-360/business/admin/ru/security-service-applications). Событие на весь день, отменённое или отклонённое приглашение, отсутствие ссылки и несколько разных ссылок дают пропуск с объяснением.

Перед запуском данные читаются заново. Ошибка календаря не означает удаления событий и не запускает встречу по старой ссылке. Перенос меняет будущий запуск; после принятого или неопределённого запуска параметры фиксируются. Автоматическое повторное подключение после прерывания звонка отсутствует.

Агент обслуживает одну встречу. Расписание заранее показывает возможные пересечения; фактическая занятость проверяется при входе. Более ранняя встреча получает приоритет, действующая запись не прерывается. Вторая встреча может войти, если агент освободится в пределах допустимого опоздания; иначе показывается причина пропуска.

Ожидание допуска ограничено десятью минутами от начала события. Запись завершается по окончании события плюс десять минут, но не позднее действующего максимума 120 минут; без окончания по умолчанию действует предел 60 минут. Штатные остановки, видимость записи и выключенные камера/микрофон сохраняются.

Пауза отменяет будущие входы. Отключение удаляет сохранённый пароль, но сохраняет историю и материалы. Уже активную запись останавливают отдельно. Неопределённый ответ на запуск проверяется по UUID сессии; после таймаута второй POST не отправляется. Если результат так и не удалось установить, интерфейс показывает неопределённость, автоматический повтор исключён.

## Доступ и хранение

Этот выпуск использует существующий личный веб-интерфейс без ключа доступа, открытый только через localhost и SSH-туннель. Подписки принадлежат локальному владельцу. Режим для нескольких веб-пользователей, привязка календаря к пользователю Telegram и корпоративный календарь ассистента требуют отдельной авторизации и маршрутизации владельцев. Автоматические записи не выдаются посетителям Telegram-бота.

Пароль календаря шифруется Fernet до сохранения в PostgreSQL. Ключ находится в secrets/calendar_key и подключён только к API и планировщику. Секретные поля не возвращаются API; ошибочные поля подключения не отражаются в ответах проверки формы. Пароль после подключения очищается, в browser storage не сохраняется. Логи планировщика содержат фиксированные коды, без ссылок, названий или ответов календаря.

Для существующей установки ключ создаёт `python3 scripts/create-calendar-key.py`; повторное выполнение сохраняет прежний ключ. Для новой установки его создаёт app.bootstrap. Каталог secrets имеет права 0700, файл доступен непривилегированному контейнеру через Docker secret. Ключ необходимо хранить отдельно от Git и резервировать вместе с базой, с соответствующим ограничением доступа. Потеря ключа требует переподключения календарей.

## Проверка и оставшаяся приёмка

В отдельном Compose-проекте с PostgreSQL на tmpfs прошли 147 тестов приложения. Проверены переносы и исключения, календарные зоны и сезонное изменение смещения, отклонённое приглашение, неправильные ссылки, неполный ответ CalDAV, шифрование, права владельца, согласие на запись, пауза между сохранением задания и контактом агента, гонка пропуска с запуском, два планировщика, два конкурентных запуска, потерянный ответ, исчезновение уже принятой сессии, истечение времени подключения и повтор запроса после дедлайна.

Браузерные проверки прошли на синтетических данных: обнаружение календарей, подключение, очищение пароля, однократное разрешение, расписание, пропуск, пауза, отключение и безопасное отображение текста. Также повторно проверены существующие загрузка и управление Телемостом. Серверные health-checks API и агента проходят, heartbeat планировщика обновляется, секрет доступен нужному контейнеру. Подключённых календарей при развёртывании нет.

Чтение целевого календаря Яндекса подтверждено. Для завершения приёмки нужны две реальные встречи по расписанию с результатом календарь → вход без ручной команды → штатная запись → импорт → транскрипт и протокол. Перенос и отмену нужно подтвердить на этом же источнике. Проверки с синтетическими данными не заменяют эти звонки.

Сохранённые записи и новые таблицы удалять не требуется. Ключ шифрования сохраняется для дальнейшего восстановления подключений.

## Исправление подключения корпоративного аккаунта

12 октября исправлен HTTP-клиент календарного подключения. При диагностике на Bender запросы через прежний транспорт получали 429 с ответом limited, а запросы через requests с того же сервера — штатный ответ авторизации 401 без учётных данных. Чтение CalDAV переведено на requests в отдельном потоке с общей HTTP-сессией на время поиска, с идентификатором psptm-minutes-calendar/1.0, без прокси окружения, перенаправлений или отключения TLS-проверки.

Ответ 429 теперь отличается от неверного пароля: API возвращает понятную причину и Retry-After. Планировщик, подготовка запуска и ручное обновление подписки соблюдают задержку. Добавлены проверки идентификации клиента, срока повторной попытки и отсутствия новых запросов во время ограничения. Успешный поиск календарей кэшируется в памяти на пять минут для тех же учётных данных: сохранение выбранного календаря не повторяет три запроса обнаружения. Пароль в кэше не хранится; при изменении учётных данных результат не переиспользуется. Проверка с учётными данными владельца завершилась успешным подключением и чтением событий.

Для обнаружения календарей используется прямой путь учётной записи /principals/users/<логин@домен>/ из [официальной инструкции корпоративной синхронизации](https://yandex.ru/support/yandex-360/business/calendar/ru/data-exchange/synchronization/sync-desktop). Это сокращает поиск до двух запросов и исключает общий корневой вход сервиса. На аккаунте владельца подтверждено успешное получение списка «Мои события» и «Не забыть»; в 10:11 МСК подписка «Мои события» сохранена, успешно прочитаны 22 события со ссылками Телемоста. Ошибки синхронизации отсутствуют. Автоматический вход выключен до однократного разрешения владельца в настройках подписки.
