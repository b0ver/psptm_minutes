# Production: точечное исправление рекордера, 7 ноября 2026

Владелец принял живой прогон 62:31 с двумя автоматическими сменами. Критерий 65 минут заменен этим решением. Полный RC сейчас также заменит код анализа и шаблоны. Эти изменения не входят в согласованную приемку рекордера.

Предложенный узкий выпуск использует только telemost-agent из commit cdbd17a19c8a487a297c457b6f40d7ff775c0ff4:

`ghcr.io/b0ver/psptm_minutes-telemost@sha256:84fa3acfb32235cdc055f2964ec89fe9f00a48a76a37bbc3ef3e1ada769834af`

API, Telegram, calendar, оба обработчика, PostgreSQL, схемы, веса и Ollama сохраняют текущие версии. Это требует прямого исключения владельца из правила AGENTS.md «не обновлять сервисы по отдельности». Владелец прямо разрешил исключение: «Разрешить точечное обновление рекордера». Разрешение относится только к этому образу рекордера. Production обновлен только в указанном объеме.

На отдельном CPU-стенде Bender выполнены импорт нового рекордера с точным текущим API, повторный импорт без дубликата, проверка байтов и отсутствия AI-обработки, девять Chromium controls. Выполнен откат на прежний образ рекордера и возврат на кандидат. Все 73 настоящих terminal-состояния загружены кандидатом без изменения файлов. Старые 12 partial_saved остаются неполными; их сохраненные файлы проверены, автоматический импорт не выполняется. [Безопасный отчет](../reports/recorder-production-staging-2026-11-07.json).

Прежний образ рекордера сохранен в архив. Его зашифрованная off-host копия проверена расшифрованием и SHA256. Ключ находится отдельно. Образы работающих worker и calendar отсутствуют в image store; эти контейнеры нельзя удалять при точечном выпуске. Исходные image ID всех семи сервисов сохранены в частном плане восстановления. Не объявлять это управляемым baseline всего приложения.

Выполненная последовательность после явного разрешения исключения:

1. Проверить неизменность контейнеров и образов исходной установки.
2. Закрыть прием: приостановить producers и API.
3. Проверить все durable-состояния агента и отсутствие активных или неопределенных импортов.
4. Удерживать queue locks при приостановке обоих consumers; при processing отменить выпуск.
5. Сохранить согласованную БД, записи, secrets, environment и текущие Compose-файлы. Проверить архивы, отдельное восстановление и зашифрованную off-host копию. Онлайн-копию записей можно использовать только при доказанной неизменности полного файлового manifest после закрытия приема.
6. Изменить только image reference telemost-agent; применить --no-build --no-deps только к нему.
7. Проверить health, прежние состояния без изменений и доступ через текущий API.
8. Возобновить API, прежние consumers и producers через unpause. Их контейнеры не пересоздаются; отсутствие исходных образов не приводит к потере работающих процессов.
9. Проверить, что версии и container ID всех остальных сервисов сохранились.

При неудаче восстановить прежний образ рекордера из сохраненного image ID или архива. Возвратить прежний Compose overlay. Не откатывать БД, если схема и данные не менялись. Не применять prune, down -v, пересборку :local или перезапуск общей Ollama. При появлении активной записи отложить выпуск. Production workflow не включать.

## Результат

Обновление завершено. [Безопасный receipt](../reports/recorder-production-2026-11-07.json) фиксирует точный digest, проверки и объем исключения. Все 73 прежних состояния не изменились. Все остальные контейнеры и image ID сохранены, ни один из них не пересоздан. Приостановленные процессы возобновлены через unpause. Новый рекордер имеет точные исходные файлы и команду запуска опубликованного образа. Текущий API успешно обращается к нему. Telegram getMe успешен; тестовое сообщение никому не отправлялось.

Данные, БД, ключи и environment имеют проверенные зашифрованные off-host копии. Полное восстановление данных и расшифрование календарного credential проверены отдельно. Тестовые контейнеры и копии восстановленных volumes удалены только после проверок; production-данные и резервные архивы сохранены. Отдельный рабочий прогон после production-переключения еще не выполнен. Протоколы двух локальных приемочных встреч не формировались.

Полный управляемый baseline приложения по-прежнему не принят. Недостающие исходные образы worker/calendar требуют отдельной подготовки восстановления; их текущие контейнеры в этом выпуске не удалялись и не перезапускались. Исключение не разрешает произвольные следующие точечные обновления или продвижение остальных образов RC.
