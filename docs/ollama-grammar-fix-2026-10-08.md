# Ошибка Ollama после успешного STT

8 октября 2026. У задания status=failed, error_code=ollama_http_error, attempts=1, транскрипт сохранён. Worker в момент ошибки не перезапускался: StartedAt 2026-10-08T12:28:03.027573721Z, RestartCount=0, OOMKilled=false. Обновления API не перезапускают worker.

Синтетический запрос без пользовательского текста воспроизвёл HTTP 400 от Ollama с признаком invalid grammar. В исходной Extraction-схеме присутствуют maxLength до 10000. После удаления только maxLength из схемы для генерации тот же синтетический запрос вернул HTTP 200, done=true, done_reason=stop и результат, прошедший исходную Pydantic-валидацию.

Исправление: ollama_extraction_schema() рекурсивно убирает maxLength из передаваемого format; структура, обязательные поля, минимальная длина и остальные ограничения остаются. Исходная Extraction.model_validate_json применяется без изменений и продолжает проверять максимальную длину. Добавлен тест, отклоняющий minutes длиной 10001 символ. 39 тестов прошли на сервере за 1.78 s.

[Документация Ollama](https://github.com/ollama/ollama/blob/main/docs/capabilities/structured-outputs.mdx) описывает передачу JSON Schema в format и проверку ответа Pydantic. Конкретная несовместимость этой схемы установлена сравнением синтетических запросов на нашем сервере, а не утверждается для всех версий Ollama.

Повторная обработка должна использовать сохранённый транскрипт. Перезапуск worker допускается после проверки отсутствия queued/processing; исходное задание возвращается в очередь только после установки исправления. Запись, транскрипт и содержимое протокола в отчёт не включаются.

## Результат применения

Перед заменой worker проверено active_jobs=0 (queued/processing отсутствовали). Новый GPU-образ установлен только для worker; Ollama и API не перезапускались в ходе этого исправления. Исходное failed-задание возвращено в очередь условным UPDATE по id, статусу, коду ошибки и наличию транскрипта; остальные задания не менялись.

Повтор завершился status=ready, error_code=null, attempts=2. Сохранены 375 сегментов, протокол содержит 2326 символов; черновиков поручений 0. STT не повторялся: process_one использует существующий транскрипт. Это подтверждает успешный полный вызов этапа Ollama на пользовательском транскрипте, но не заменяет проверку качества протокола человеком. Содержимое транскрипта/протокола в инструменты вывода не передавалось.
