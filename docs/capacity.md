# Измерение мощности альфы

Считать завершённые встречи со всеми запрошенными разделами, отдельно live-запись и загруженные файлы. В отчёте указать commit, image digest, модели/digest, GPU, выбранные шаблоны, размер/длительность и фоновую нагрузку. Не публиковать транскрипты, источники, имена и ответы AI.

Разрешённое расписание и условия запуска: [capacity-schedule.md](capacity-schedule.md). Будни 07:00–09:00 MSK, выходные; перед каждым запуском проверка доступности и подготовленный watchdog.

## Изолированный полный прогон

`benchmarks/capacity.py` выполняет настоящие STT, основной протокол и production-разбор с выбранными шаблонами. БД, очередь и данные отдельные; рабочие secrets/volumes не подключаются. Используется общая хостовая Ollama и GPU: запускать в согласованное окно, без обучения и других inference-потребителей. Это измеряет последовательный полный цикл, а не реальную конкурентность двух production workers и не запись Телемоста.

Контейнер работает под UID 10001: каталог corpus и записи должны читаться этим UID. Предпочтительно ACL или соответствующая группа; разрешён и читаемый bind-каталог внутри внешнего защищённого каталога 0700. Не менять права исходных production-записей; работать с копиями. `PYTHONPATH=/app` в Compose требуется для запуска смонтированного `/capacity.py`.

На Linux/NVIDIA подготовить полный контекст точного commit, отдельный образ и два новых контейнера без запуска по [контракту watchdog](capacity-watchdog.md). Параметры CAPACITY_CORPUS_DIR/STT_MODEL_DIR/STT_MODEL_PATH указывают на разрешённые копии и существующие веса; OLLAMA_MODEL — на разрешённый digest. Не менять права исходных записей. Запуск выполняется только через серверную защиту:

```sh
python3 scripts/ops/capacity_watchdog.py check /absolute/private/run/job.json
python3 scripts/ops/capacity_watchdog.py start /absolute/private/run/job.json
```

Контроллер использует уже созданные контейнеры, сохраняет приватные logs/dump и останавливает только их. Прямой `compose run --build` обходит окно/приоритет/watchdog и для запусков по расписанию не используется. Перед удалением собственной завершённой попытки сохранить метрики и данные для человеческой проверки; не выполнять автоматический `down --volumes` до этого. Никогда не подменять project/Compose рабочими.

Вывод содержит длительности, статус и коды ошибок. `speech_end_seconds` — конец последнего речевого сегмента, а не длительность всего исходного медиа; реальную длительность фиксировать отдельно. `p95` — nearest rank, на трёх примерах почти максимум, статистически слабая оценка. `planning_meetings_per_budget` выдаётся только при полном успехе, с резервом 40%; `validated_daily_capacity` всегда false. Если основной протокол failed, анализ может продолжить работу с сохранённым транскриптом; встреча всё равно не считается полной успешной обработкой.

## Программа приёмки

1. 30 независимых встреч: 30/60/120 минут, чистый/шумный звук, разные жанры, 1/5/16 шаблонов. Отдельно результаты на пустом, повреждённом и >120 минут файле. Фиксировать p50/p95 по профилю, ошибки, время ожидания и фактическую точность вручную.
2. На отдельном staging запустить обе очереди, проверить серию загрузок и рост очереди. Ограничения записи: второй одновременный звонок, ожидание допуска, отсутствие модератора, отмена/перенос календаря. Не создавать звонки реальным сотрудникам как часть CI.
3. 24 часа soak при ожидаемом корпоративном профиле: нагрузка 50%, 70%, затем короткий burst. Записывать размер/возраст очереди, время до всех разделов, сбои, VRAM/RAM, диск и фоновую конкуренцию. Должны отсутствовать потерянные/зависшие задания и непрерывный рост очереди после burst.
4. Отказы на staging: перезапуск worker, недоступность Ollama, Telegram 429, потерянный ответ импорта, SIGKILL агента на синтетическом звонке. Проверить частичную запись, отсутствие дублей и последующее восстановление.
5. Утвердить дневную квоту ниже устойчивого наблюдаемого предела с резервом ≥40%, отдельную квоту времени live-агента, лимит одновременно ожидающих заданий и время ответа пользователю. Два workers на одном GPU требуют фактического замера; формула последовательного стенда не гарантирует, что совместная работа быстрее.

Дневную квоту нельзя считать числом пользователей. Пилот начинать с вручную ограниченного приёма и фиксировать факт, что сейчас программных квот нет. Расширять допуск только после измерения.


## Проверка пути STT перед подготовкой

STT_MODEL_DIR задает корень bind mount. STT_MODEL_PATH задает каталог модели внутри контейнера. Эти каталоги могут различаться. Для кэша со snapshots укажи конкретный snapshot в STT_MODEL_PATH. Приложение требует model.bin, config.json и tokenizer.json непосредственно в этом каталоге. Перед GPU проверь эти файлы под UID 10001 через app.settings.MODEL_PATH в выбранном образе без сети и GPU. Сам факт чтения корня весов не подтверждает правильный путь. Сохрани проверенный путь и хеши в отдельном приватном manifest. Не меняй существующие веса. В GPU-образе нет ffprobe; длительность входа можно получить через установленный PyAV без CUDA.
