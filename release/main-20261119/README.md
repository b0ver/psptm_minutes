Проверенная подготовительная версия f6e2ebf: полный Docker/PostgreSQL suite 428 PASS / 0 FAIL, 2 предупреждения, linux/arm64. Установленные версии runtime совпали с lock; pip check прошел. Аудит Python: 0 известных уязвимостей в 49 пакетах runtime и 21 пакете recorder. Это не оценка ОС, браузера или качества настоящих AI-результатов. Публикационная версия также прошла 428 тестов на linux/arm64: 89,22 секунды, 2 предупреждения. Она требует собственного native CI. Дополнительные девять проверок OS manifest и ELF probe прошли.

Позже исправлен только поиск процесса в аварийном browser probe: точный executable, UID и профиль из CDP. Рабочая логика рекордера не изменена. ## Откат и восстановление

У исходных worker и calendar-scheduler отсутствовали слои старых image ID. Их рабочие контейнеры не останавливали. Из readonly rootfs созданы отдельные локальные образы отката. Код, установленные пакеты, Python, OS identity и runtime config совпали со снимками контейнеров. Это восстановленные образы с новыми image ID, а не исходные image ID.

Оба образа прошли по два холодных запуска на пустой изолированной PostgreSQL linux/amd64. Производственные mounts, credentials, Telegram, встречи и модели не подключались. Эта проверка не заменяет candidate-to-previous rollback на восстановленной актуальной БД.

Код текущей попытки b4 находится в restore-tools-b4. Он прошел 121 native тест; одна unit-проверка GPG пропущена в контейнере без GPG. Настоящая зашифрованная off-host копия настроек прошла расшифровку и проверку SHA256.

Попытка b3 остановлена после обнаружения Docker logging копии бинарного потока. Ее reader унаследовал json-file logging. Локальный служебный лог достиг 44,5 ГБ. Остановка только owned reader/writer удалила этот временный лог через штатный --rm. Диагностика b3 сохранена. Удалены 9,5 ГБ только неполной изолированной копии b3. Исходный архив и вся цепочка deltas остались без изменений. Старые b1/b2 и frozen controllers не менялись.

В b4 оба контейнера используют --log-driver none. Контроллер проверяет ownership, image, фактический LogConfig.Type=none и пустой LogPath. Native запуск подтвердил этот контракт. Stdout reader подключен к stdin writer. В журнал контроллера попадают только агрегаты. Попытка не восстанавливает данные поверх production.

Контроллер проверяет три NAS блокировки и неизменность четырех последних записей. Checkpoint означает наблюдаемую паузу NAS, а не его приемку. Пауза при нехватке ресурсов выполняется в userspace. Сохраняются монотонная lease, boot ID, запас диска 60 GiB и прежние пороги PSI. Потеря контроллера приводит к отказу lease через 30 секунд. Для продолжения нужны две свежие успешные проверки. Ожидание ограничено часом внутри общего лимита шесть часов. Чтение и запись вместе ограничены 8 МиБ/с.

Native worker прошел synthetic previous -> candidate -> previous на общей изолированной PostgreSQL. Проверены реальные запуски и session lock, завершение synthetic jobs и сохранение прежних результатов. Extractor был явной синтетической функцией; модели и GPU не использовались. Это еще не откат на восстановленной актуальной БД.

Перед выкладкой требуется восстановить актуальную цепочку, свежую БД и соответствующие secrets/settings. Затем требуется проверить ссылки файлов и ключ календаря. Малый пакет secrets/settings должен пройти зашифрованную off-host проверку.

## Сборка и приемка

Release alpha запускается в candidate_only=true на ветке codex/main-release-20261119. Draft main-2026.11.19-rc.1 сначала хранит private native transport с тремя image ID и SHA256 архивов. После локальной проверенной публикации main-rc-bundle.json содержит три immutable registry digest и source commit. Пока acceptance_complete=false, этот файл не разрешает deployment. Production workflow не активируется.

После успешного native CI нужны inventory и scoped OS review, изолированный staging, полный rollback, актуальный restore и проверка доступа двух подтвержденных операторов. Проверка дубликатов и сохранности файлов обязательна. Production smoke не создает настоящие встречи. Перед переключением закрывается прием, останавливаются producers, проверяются все состояния агента и processing, затем удерживаются queue locks при остановке consumers. Здоровая запись никогда не прерывается ради выкладки.

## Неизменяемый комплект и инструменты приемки

Три образа собраны из c5d0059162ba2eae72c3c56dd378affb53a34aa8. Native CI 44608668533 завершился успешно: 431 тест приложения, security gates и восемь браузерных probes. Все три образа опубликованы в существующих private packages и доставлены без передачи registry credentials на Bender.

Классическое Docker хранилище сообщает config digest как image ID. Containerd image store на Bender сообщает OCI manifest digest. Проверка доставки связывает оба значения через исходный OCI manifest, сравнивает полную Config и упорядоченные rootfs diff IDs. Совпадение source commit и платформы проверяется отдельно. Эти различия представления не требуют пересборки на production.

B4 исправляет только отдельный инструмент приемки. Исходный commit трех образов остается c5d0059; revision инструментов и итоговые доказательства фиксируются отдельно. Production и release draft пока не опубликованы как принятый релиз.

Production-сервисы не менялись.

[Оценка применимости OS advisories](os-applicability-20261120.md) ограничена текущим закрытым пилотом. Она не объявляет все установленные пакеты исправленными.

Отдельный набор current-restore-tools-v3 проверяет текущий delta поверх восстановленных 85 архивов. Он сохраняет цепочку хешей извлечения, проверяет inode/ctime/metadata предыдущей копии и целостность новых архивов до записи. Следующий delta использует proof предыдущего. Исходные recordings всегда подключены readonly. Служебные runtime symlinks исключаются только по отдельно проверенному точному descriptor. Удаление persistent файлов отражается в плане.

Финальный frozen admission требует остановки всех шести исходных приложений и работающей исходной PostgreSQL. Он проверяет точные container/image IDs, все durable состояния и processing очереди. Для чтения состояний после остановки API используется отдельный readonly контейнер. Замена контейнера, перезапуск приложения или новая запись закрывает допуск. Шесть проверок frozen admission и 13 проверок delta прошли в Docker на arm64 и native amd64. Проверки не выполняли production cutover.

Текущая БД будет снята через readonly REPEATABLE READ и exported snapshot, общий с pg_dump. На отдельной БД проверяются все таблицы, ссылки recordings, import hashes и расшифровка календарных credentials ключом из проверенной копии настроек. Затем требуется previous/candidate/previous worker rollback на этой БД. Эти настоящие проверки пока ожидают завершения B4. Подготовленный private Compose сохраняет существующие volumes, networks и PostgreSQL. Он еще не запущен. Перед запуском требуется фактический cutoff уведомлений и финальная согласованная копия. Автовыход и модельная политика не изменены.

Readonly сверка источника подтвердила 88 terminal sessions, неизменность 14 старых partial_saved и отсутствие pending recovery events. Два оператора имеют активные private chat bindings. Processing и eligible analysis jobs отсутствуют. Пять старых failed-встреч без транскрипта сохраняют waiting_transcript и 25 ожидающих отчетов; новый релиз не ставит их на повторную обработку. Перед переключением проверка выполняется заново.

Подготовленный freeze controller не пересоздает сервисы. Он удерживает настоящие queue locks во время остановки consumers. Финальное ожидание ограничено 20 минутами. До принятой передачи управления он возвращает только исходные контейнеры с теми же ID. Перед передачей проверяются актуальный delta, frozen DB restore, стабильная metadata источника и подтвержденная encrypted off-host копия. Контроллер еще не запускался.

Финальный архив после остановки приема дополнительно включит свежий database.dump и фактический cutoff уведомлений. Подготовительная копия не заменяет этот финальный шаг.
