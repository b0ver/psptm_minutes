# Основной кандидат, 19 ноября 2026

Production еще не обновлен. Этот каталог описывает подготовку полного комплекта runtime, gpu и telemost из одного commit. Допуск к выкладке остается закрыт до приемки образов, восстановления актуальной копии, проверки отката и безопасного переключения.

## Код и зависимости

Кандидат содержит исправление ручного stop Telegram и восстановленную обработку длинных отчетов. 404 оставляет неизвестный результат остановки. Карточка сообщает о потере связи. Подтверждение называет выбранную встречу. Ограниченные повторы и обработка полного реестра устраняют прежние 26 ошибок suite. Тесты не ослаблялись.

Проверенная подготовительная версия f6e2ebf: полный Docker/PostgreSQL suite 428 PASS / 0 FAIL, 2 предупреждения, linux/arm64. Установленные версии runtime совпали с lock; pip check прошел. Аудит Python: 0 известных уязвимостей в 49 пакетах runtime и 21 пакете recorder. Это не оценка ОС, браузера или качества настоящих AI-результатов. Публикационная версия также прошла 428 тестов на linux/arm64: 89,22 секунды, 2 предупреждения. Она требует собственного native CI. Дополнительные девять проверок OS manifest и ELF probe прошли.

Рабочие app, config, integrations и tests перенесены из проверенной подготовки без изменения поведения. Отдельный публикационный commit не переносит приватную историю подготовки, настройки операторов и старые лабораторные материалы. Модельная политика не изменена. Автовыход остается отдельной задачей.

## ОС и браузер

install_os.py проверяет размер и SHA256 каждого официального DEB перед установкой. Runtime получает 20 закрепленных пакетов ОС. Recorder получает 31 пакет, включая официальный Chrome Stable 158.0.8127.36-1. Manifest содержит адреса, версии и хеши. Свежие подписанные метаданные Google и локальный DEB совпали с этими значениями. Подтверждение: chrome-provenance.json.

Chrome выбран в рамках поручения владельца. Образы остаются в трех private GHCR packages этого релиза. Workflow проверяет visibility перед публикацией рабочих образов. При первом создании пакета отправляется только пустой образ с публичными labels. После подтверждения private visibility workflow может отправить рабочий образ. Действующие права старых пакетов не меняются. Бинарные компоненты браузера не размещаются в публичных Git или artifacts. Условия: https://www.google.com/chrome/terms/. Опциональный Widevine удаляется из образа. Сохраняются уведомления остальных компонентов. Отключены вход в браузер, синхронизация, метрики и облачная отчетность. Плановые задания обновления и отдельный APT-репозиторий Chrome удаляются. Обновления браузера проходят через новый проверенный образ.

Путь /usr/bin/chromium остается совместимой ссылкой для существующих probes. Рабочий CHROMIUM_EXECUTABLE_PATH указывает на /opt/google/chrome/chrome. Контейнер остается под UID10001. Новых capabilities, host devices или Docker socket нет. Правила окончания встречи и управления записью не изменены. Байт-в-байт сравнение lifecycle.js, meeting_observer.js, recording_controls.py, rollover.py, checkpoint.js и browser_session.py с production прошло.

Native browser probes, фактический inventory ОС и применимость остаточных OS advisories еще должны пройти на итоговых образах. Наличие официального Chrome не закрывает эти условия. Runtime release поддерживает linux/amd64. Локальный arm64 используется для тестов Python; этот путь не подтверждает hardening ОС release-платформы.

## Откат и восстановление

У исходных worker и calendar-scheduler отсутствовали слои старых image ID. Их рабочие контейнеры не останавливали. Из readonly rootfs созданы отдельные локальные образы отката. Код, установленные пакеты, Python, OS identity и runtime config совпали со снимками контейнеров. Это восстановленные образы с новыми image ID, а не исходные image ID.

Оба образа прошли по два холодных запуска на пустой изолированной PostgreSQL linux/amd64. Производственные mounts, credentials, Telegram, встречи и модели не подключались. Эта проверка не заменяет candidate-to-previous rollback на восстановленной актуальной БД.

Код действующей изолированной попытки находится в restore-tools. Он проверен 62 синтетическими тестами; одна проверка GPG пропущена в локальном контейнере без GPG. Старые контроллеры и неполные volumes сохранены. Новый target расположен отдельно от production и старых попыток. Архивы читаются только для чтения. SHA256 входа проверяется в одном проходе с безопасным извлечением. Никакие данные из проверки не восстанавливаются поверх production.

Текущий NAS checkpoint принят только как наблюдаемая пауза, не как успешная приемка NAS. Контроллер проверяет все три существующие блокировки и неизменность четырех последних записей. Изменение NAS прерывает попытку. Временный отказ ресурса ставит только контейнеры этой попытки на паузу. Для продолжения нужны две новые успешные проверки. Ожидание ограничено 15 минутами. Вся попытка ограничена шестью часами, как предыдущая проверенная процедура. Пропускная способность учитывает чтение и запись вместе: 8 МиБ/с. Перед выкладкой требуется восстановить актуальную цепочку, свежую БД и соответствующие secrets/settings, затем проверить ссылки файлов и ключ календаря. Малый пакет secrets/settings должен пройти зашифрованную off-host проверку.

## Сборка и приемка

Release alpha запускается в candidate_only=true на ветке codex/main-release-20261119. Draft main-2026.11.19-rc.1 хранит main-rc-bundle.json с тремя immutable digest и source commit. Пока acceptance_complete=false, этот файл не разрешает deployment. Production workflow не активируется.

После успешного native CI нужны inventory и scoped OS review, изолированный staging, полный rollback, актуальный restore и проверка доступа двух подтвержденных операторов. Проверка дубликатов и сохранности файлов обязательна. Production smoke не создает настоящие встречи. Перед переключением закрывается прием, останавливаются producers, проверяются все состояния агента и processing, затем удерживаются queue locks при остановке consumers. Здоровая запись никогда не прерывается ради выкладки.
