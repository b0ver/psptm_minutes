# psptm_minutes

Локальные протоколы встреч и внутренний реестр поручений. Приложение работает в Docker; существующая Ollama остаётся на хосте. Telegram служит интерфейсом управления: статусы, карточки поручений после утверждения человеком и Markdown материалов по явному запросу владельца. Первичные записи и AI-обработка остаются локальными.

Актуальное состояние на 9 октября 2026: [статус проекта](docs/implementation-status.md). Датированные отчёты описывают отдельные этапы; ограничения и результаты проверок указаны в них на соответствующую дату.

## Что реализовано

- Web-интерфейс на русском без ключа доступа, для личной работы через SSH-туннель; без фиксированного ограничения размера файла. Загрузка показывает процент и переданный объём, затем сохранение на сервере и передачу на обработку.
- 16 типов разборов из Telemost Meeting Kit: выбор при загрузке и добавление к существующей встрече, факты и отчёты кэшируются. [Решение и ограничения](docs/adr/0003-meeting-kit-analysis-and-templates.md).
- Видимый гостевой ассистент Телемоста: вход по ссылке, штатная локальная запись, передача в очередь транскрибации. [Запуск](integrations/telemost/README.md), [ADR 0004](docs/adr/0004-telemost-visible-local-recorder.md).
- PostgreSQL: очередь, транскрипты с временными метками, протоколы, поручения, версии, аудит и transactional outbox.
- Worker: локальная STT через faster-whisper и прямой API существующей Ollama. Длинный транскрипт обрабатывается частями без пропуска сегментов.
- Allowlist моделей с digest; запрет cloud/remote-моделей и публичного AI endpoint. Нет облачного fallback, автоматического скачивания весов или пользовательского выбора провайдера.
- Черновики поручений с цитатой-основанием. Срок задаёт человек; ответственный сохраняется автоматически только если имя присутствует в цитате. AI-черновик всё равно требует проверки.
- Редактирование черновика, явное утверждение, статусы «в работе»/«выполнено». Повторное утверждение одной версии не создаёт вторую запись outbox.
- Telegram-бот: личное меню, запись Телемоста с подтверждением, выбор разборов, статусы, утверждённые поручения, устойчивые команды и long polling. Вход может быть открыт всем; материалы доступны только владельцу.

Ollama в Compose отсутствует. Общие контейнеры, базы и прокси сервера не используются. Код не меняет настройки Ollama.

## Локальный запуск интерфейса

Команды ниже описывают запуск **на машине разработки** из каталога проекта. Текущее серверное развёртывание и отдельный адрес через SSH-туннель описаны в [отчёте](docs/deployment-2026-10-08.md). Личный доступ без ключа принят в [ADR 0002](docs/adr/0002-personal-access-without-key.md).

```sh
docker build --target runtime -t psptm-minutes:local .
mkdir -p secrets
docker run --rm --network none --user "$(id -u):$(id -g)" \
  -v "$PWD/secrets:/bootstrap" psptm-minutes:local python -m app.bootstrap
docker compose up -d --build api
```

Интерфейс: [http://127.0.0.1:18190](http://127.0.0.1:18190).
Вход и ключ не требуются: выберите запись и нажмите «Загрузить и обработать». Порт опубликован только на loopback; доступ к серверу через SSH-туннель. Доступны записи и изменение реестра всем пользователям и процессам с доступом к этому порту. Изменения из браузера с постороннего Origin отклоняются. Для будущего сетевого доступа нужна отдельная авторизация.

Bootstrap не показывает секреты и не перезаписывает существующие. Каталог secrets имеет режим 0700; отдельные файлы 0644 для чтения непривилегированным UID контейнера через bind-backed Compose secrets. Копировать секреты только с сохранением защиты каталога. Секреты исключены из Git и build context.

По умолчанию запускаются только PostgreSQL, одноразовая инициализация новой схемы и API. Загрузка сохраняет запись локально в очереди. Worker и Telegram запускаются отдельными профилями.

## Подключение локальной обработки

1. Подготовить каталог CTranslate2-модели Whisper заранее: model.bin, config.json, tokenizer.json и остальные файлы модели. На Bender уже подключена large-v3 и проверен GPU-инференс; эти шаги нужны для нового развёртывания.
2. Указать STT_MODEL_DIR в локальном .env, скопировав настройки из .env.example. Каталог монтируется только для чтения. Отсутствующий каталог не создаётся автоматически.
3. Убедиться, что нужная разрешённая модель уже есть в Ollama на хосте запуска Docker. Docker Desktop на Mac будет обращаться к Mac, а Docker Engine на Ubuntu — к Ubuntu; адрес host.docker.internal относится к хосту соответствующего Docker, не автоматически к 192.168.1.90.
4. Для включения обработки в новом развёртывании:

```sh
docker compose --profile ai up -d worker analysis-worker
```

В config/models.json закреплены digest qwen3.5:9b и qwen2.5:14b-instruct из обследования; первая — стартовый кандидат, а не модель с уже подтверждённым качеством. Worker сверяет каталог перед каждым запросом. В процессе обработки менять теги Ollama нельзя: API tags/check и chat не образуют атомарную транзакцию.

Базовый образ поддерживает CPU int8, а отдельный GPU-образ — CUDA float16 без автоматического перехода на CPU. STT освобождает модель перед вызовом Ollama; другие приложения по-прежнему могут одновременно использовать общую GPU. Декодер допускает только локальные протоколы file/pipe и ограничивает длительность записи двумя часами.

### Whisper large-v3 на GPU

На сервере использовать существующий каталог модели целиком (snapshots вместе с blobs), монтируя только для чтения. Серверные значения STT_MODEL_DIR и STT_MODEL_PATH заданы в .env; путь внутри контейнера указывает на закреплённый snapshot large-v3. Это сохраняет относительные ссылки Hugging Face без копирования или скачивания весов.

```sh
docker compose -f compose.yaml -f compose.gpu.yaml --profile ai build worker
docker compose -f compose.yaml -f compose.gpu.yaml --profile ai run --rm --no-deps -T worker python -m app.check_stt
docker compose -f compose.yaml -f compose.gpu.yaml --profile ai up -d --no-deps worker analysis-worker
```

Overlay меняет только worker: отдельный psptm-minutes:gpu, GPU 0, STT_DEVICE=cuda и STT_COMPUTE_TYPE=float16. CUDA cuBLAS/cuDNN устанавливаются внутри Docker; runtime и драйвер хоста не меняются. GPU требует Linux/NVIDIA Container Toolkit и доступной видеокарты; это не профиль для Docker Desktop на Mac. Проверка check_stt загружает существующую модель и выполняет настоящие CUDA-ядра на одной секунде синтетической тишины, не читая пользовательские записи и не вызывая Ollama.

[GPU-проверка и включение large-v3](docs/gpu-stt-2026-10-08.md): CUDA float16 подтверждена настоящими вычислениями; постоянный серверный worker включён, модели подключены только для чтения. Обработка реальных записей также выполнена; сравнительная оценка качества моделей ведётся отдельным бенчмарком.

Части протокола соединяются последовательно, без дополнительного глобального AI-синтеза. Диаризация и определение участников по голосу не реализованы. Ошибки постоянной конфигурации завершают задание с безопасным кодом; временные ошибки сети Ollama повторяются до трёх попыток. Автоматическое восстановление processing-задач происходит после перезапуска worker с получением эксклюзивного advisory lock.

## Telegram

Токен хранится в локальном `.env` проекта в `TELEGRAM_TOKEN` либо в `secrets/telegram_token`. Если используются оба источника, их значения должны совпадать; файл `DISABLED` считается пустым. Не сохранять токен в Git и не выводить его в журналы.

Для открытого входа установите `TELEGRAM_ENABLED=1` и `TELEGRAM_ALLOW_ALL=1`. Для ограниченного входа оставьте `TELEGRAM_ALLOW_ALL=0` и задайте числовые ID через `TELEGRAM_ALLOWED_USERS`. `TELEGRAM_CHAT_ID` новой версии интерфейса не требуется: ответы отправляются в личный чат владельца.

```sh
docker compose run --rm init
docker compose --profile telegram up -d --no-deps telegram
```

Групповая статистика разрешается только для числового `TELEGRAM_STATS_CHAT_ID`. В выбранной группе `/stats@имя_бота` показывает общие счётчики приложения, `/stats@имя_бота today` — за сегодня по Москве. Доступны кнопки обновления и переключения периода. Группа получает только цифры; личные материалы остаются доступны владельцам в личных чатах. Учёт обращений начинается с включения этой версии и означает входящие сообщения/нажатия, а не вызовы AI. За сегодня встречи считаются по дате загрузки, разборы и отчёты — по последнему обновлению; пользователи и поручения показываются текущим итогом.

Бот использует long polling без входящего порта и webhook. `/start` открывает меню, `/meetings` — свои встречи, `/tasks` — утверждённые поручения, `/status` — свои записи, `/telemost` — создание записи, `/cancel` — отмену диалога. Ссылка Телемоста сначала открывает форму: название, длительность и типы разборов. Запись начинается только после явного подтверждения разрешения участников. Один агент обслуживает одну встречу одновременно.

Каждая сессия и импортированная встреча связаны с Telegram user ID. Чужие кнопки проверяются на сервере. Старый архив и его outbox не выдаются новым пользователям. Загруженные через локальный веб-интерфейс записи автоматически никому не назначаются. Исходные записи и AI-обработка остаются локальными. По явной команде владельца бот передаёт через Telegram Markdown транскрипта, отдельного готового отчёта или всех готовых разделов встречи. В группе файлы и персональные материалы не выдаются. Бот не скачивает присланные аудио/видео и не публикует общий веб-архив.

Команды, диалоги, очередь сообщений и offset хранятся в PostgreSQL. Повтор запуска использует прежний UUID и проверяет результат; повторной встречи не создаёт. Доставка Telegram может дублироваться при потере ответа после отправки. Ошибки 429 откладывают повтор, блокировка бота отключает доставку пользователю. Утверждённые поручения можно перевести в работу или завершить; изменения сохраняются с аудитом.

## Проверки в Docker

```sh
docker compose -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests
docker compose -f compose.test.yaml down
```

Это отдельный Compose-проект и PostgreSQL на tmpfs без опубликованных портов. Тесты проверяют загрузку, очередь и создание черновиков с подставными STT/LLM, запрет облачных моделей, digest, доказательные цитаты, гонку утверждения, версии и immutable approval, outbox, ограниченные retries и ACL/idempotency Telegram. Telegram и Ollama подставные; отправки, скачивания весов и настоящего инференса нет.

Образ Python и PostgreSQL закреплены digest; Python-пакеты runtime закреплены в requirements.lock. requirements.txt содержит исходные прямые зависимости. Тесты выполнены на локальном Docker Desktop arm64; проверка linux/amd64 на целевом сервере ещё нужна.

## Границы текущего этапа

API, PostgreSQL и GPU worker large-v3 развёрнуты на 192.168.1.90 в отдельном проекте. После интеграции разборов на сервере прошли 52 теста, включая очередь/кэш отчётов, доказательные цитаты, отсутствие CPU fallback и освобождение STT модели при ошибке. Диагностический контейнер проверил доступ к хостовой Ollama и digest локальной модели; отдельная проба подтвердила CUDA STT. Telegram развёртывается отдельно; актуальное состояние описано в `docs/deployment-telegram-2026-10-09.md`. Настоящие пользовательские записи транскрибируются локально; очередь новых шаблонных разборов включена. Проверка Telegram описана в отдельном отчёте развёртывания. Полная изоляция исходящего трафика AI-сети требует отдельно разрешённых правил firewall: bridge-сеть worker сама по себе не запрещает интернет, а настройки локальных клиентов не являются сетевым фильтром. Egress существующей Ollama тоже не изменялся.

Перед эксплуатацией определить политику хранения/удаления и backup/restore, замерить ресурсы, проверить модель на русскоязычных записях и утвердить сетевые ограничения. Инициализация create_all создаёт отсутствующие таблицы; изменения колонок существующих таблиц требуют миграций.

[Архитектурное решение](docs/adr/0001-docker-host-ollama-local-processing.md).

[Результат локальной проверки](docs/implementation-status.md): 31 тест в Docker и Chrome smoke входа/выхода, навигации и очистки ключа. Для повторного browser smoke запустить локальный API и выполнить `node scripts/browser-smoke.mjs` (Node с встроенным WebSocket, Chrome; путь можно указать через CHROME_PATH). Скрипт проверяет немедленную доступность пространства и формы без ключа, заполнение названия по имени файла, загрузку и навигацию. Синтетическая загрузка перехватывается в тестовом браузере; задания на сервере не создаются. Снимок содержит только синтетические данные.

Проверить только доступ к Ollama без инференса можно отдельной командой в Docker на хосте её службы:

```sh
docker compose --profile diagnostics run --rm --no-deps -T ollama-check
```

[Интеграция Telemost Meeting Kit и проверка](docs/meeting-kit-integration-2026-10-08.md): 16 типов разборов, отдельный analysis-worker, применение к текущим транскриптам.

[Надёжность ассистента Телемоста](docs/adr/0005-telemost-durable-recording-and-idempotent-import.md): аудиофрагменты на локальном диске, восстановление неполной записи и повтор импорта без дублей.

[Исследование Telegram-интерфейса](docs/telegram-interface-research-2026-10-08.md): меню встреч, управление разбором, поручения, уведомления и варианты доступа к приложению. Базовый интерфейс реализован; планы расписания и поиска остаются в бэклоге.

## Доступ вне домашней сети и Markdown

Bender доступен по SSH через Tailscale: `epopov@100.111.184.29`. API слушает localhost сервера. На этом Mac настроен SSH-туннель, веб-интерфейс: http://127.0.0.1:18192/. Для открытия с другого компьютера с доступом SSH и Tailscale:

```sh
ssh -N -L 127.0.0.1:18192:127.0.0.1:18190 epopov@100.111.184.29
```

В боте: «Мои встречи» → встреча → «Скачать Markdown» → транскрипт, готовый раздел разбора или все готовые разделы. Это явная передача содержимого через облачный Telegram по просьбе пользователя; первичные записи и AI-обработка остаются локальными. В очереди хранится ссылка на материал, владелец перепроверяется перед отправкой. Неполная запись помечается в Markdown. Старые веб-загрузки автоматически Telegram-пользователям не назначаются.

Телемост: камера выключается с проверкой UI, название берётся из встречи, а имена и наблюдаемые роли сохраняются локально. Привязка реплик по активной плитке предварительная, без угадывания должностей. Подробнее: [камера, спикеры и название](docs/telemost-camera-speakers-title-2026-10-09.md).
